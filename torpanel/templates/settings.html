CF

Managed Inbound مناسب Cloudflare CDN

به‌جای یک Inbound عمومی برای هر Location، یک VLESS + WebSocket + TLS مشترک می‌سازد و هر Location را با Client اختصاصی به Tor Exit خودش Route می‌کند.

Certificate خود پنل: پروژه مسیرهای webCertFile و webKeyFile را مستقیماً از API خود 3x-ui می‌خواند و همان Certificate را روی Inbound TLS استفاده می‌کند؛ Private Key از سرور خارج نمی‌شود و فقط مسیر فایل به Xray داده می‌شود.
Cloudflare: WebSockets باید فعال باشد و SSL/TLS روی Full (strict) قرار گیرد. این پروفایل برای CDN استاندارد از WebSocket/HTTPS استفاده می‌کند؛ REALITY و WireGuard خام از Proxy عادی Cloudflare عبور نمی‌کنند.
WP

WARP Assist برای سایت‌های مشکل‌دار

فقط دامنه‌هایی که مشخص می‌کنی از Cloudflare WARP خارج می‌شوند؛ بقیه ترافیک همچنان از Tor همان Location عبور می‌کند.

نصب WARP روی همین سرور
sudo /opt/tor-location-manager/scripts/install-warp
بعد از بروزرسانی پروژه، این دستور رسمی Cloudflare WARP را نصب و در Local Proxy mode راه‌اندازی می‌کند.
محدودیت: WARP تضمین نمی‌کند هر سیستم ضدربات تأیید شود؛ Reputation، Cookie، JavaScript و Fingerprint هم می‌توانند در Challenge مؤثر باشند.
IR

سازگاری Tor با سرور ایران / شبکه محدود

Direct برای حالت عادی و obfs4 برای شبکه‌ای که bootstrap مستقیم Tor مسدود است.

نکته: فعال‌کردن Bridge بدون Bridge معتبر باعث می‌شود Tor instanceها بالا نیایند.

همان Certificate و Private Key ثبت‌شده در 3x-ui را به‌صورت محلی و امن برای این پنل استفاده می‌کند تا به‌جای IP با دامنه وارد شوید.

بعد از فعال‌سازی: مثلاً اگر 3x-ui روی https://panel.example.com:2053 باشد و پورت 2096 را انتخاب کنید، Tor Location Manager با https://panel.example.com:2096 باز می‌شود.

شرط مهم: برای استفاده مستقیم از فایل‌های SSL، 3x-ui و Tor Location Manager باید روی همان سرور باشند. اگر 3x-ui روی سرور دیگری باشد، سیستم فعال‌سازی را متوقف می‌کند و HTTP فعلی را خراب نمی‌کند.
تمدید خودکار: مسیر Certificate اصلی 3x-ui ذخیره می‌شود و Timer سیستم هر چند ساعت تغییر Certificate را Sync می‌کند؛ Private Key فقط روی همان سرور کپی می‌شود و در دیتابیس یا UI نمایش داده نمی‌شود.
