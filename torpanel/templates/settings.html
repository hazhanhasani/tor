CF

Managed Inbound مناسب Cloudflare CDN

به‌جای یک Inbound عمومی برای هر Location، یک VLESS + WebSocket + TLS مشترک می‌سازد و هر Location را با Client اختصاصی به Tor Exit خودش Route می‌کند.

Certificate خود پنل: پروژه مسیرهای webCertFile و webKeyFile را مستقیماً از API خود 3x-ui می‌خواند و همان Certificate را روی Inbound TLS استفاده می‌کند؛ Private Key از سرور خارج نمی‌شود و فقط مسیر فایل به Xray داده می‌شود.
Cloudflare: WebSockets باید فعال باشد و SSL/TLS روی Full (strict) قرار گیرد. این پروفایل برای CDN استاندارد از WebSocket/HTTPS استفاده می‌کند؛ REALITY و WireGuard خام از Proxy عادی Cloudflare عبور نمی‌کنند.
WP

Cloudflare WARP داخل خود 3x-ui

WARP از API رسمی 3x-ui ثبت می‌شود و یک Outbound واقعی warp از نوع WireGuard داخل Xray می‌سازد؛ دیگر Local Proxy جدا روی Tor Gateway لازم نیست.

وضعیت 3x-ui WARP: {% if xui_warp_status.outbound and xui_warp_status.registered %} Registered و Outbound warp فعال است. {% elif xui_warp_status.outbound %} Outbound warp موجود است؛ وضعیت Registration کامل تأیید نشد. {% elif xui_warp_status.registered %} WARP Register شده ولی Outbound warp هنوز داخل Xray Config نیست؛ Save تنظیمات آن را می‌سازد. {% else %} هنوز WARP در 3x-ui آماده نیست؛ Save تنظیمات آن را Register می‌کند. {% endif %} {% if xui_warp_status.error %}
{{ xui_warp_status.error }}{% endif %}
برای CAPTCHAهای Cloudflare: CDN فقط مسیر ورودی را Cloudflare می‌کند؛ Reputation خروجی کاربر را تغییر نمی‌دهد. WARP اینجا برای سایت‌های انتخابی خروجی را از Tor به Cloudflare WARP می‌برد و Challenge هم روی همان خروجی نگه داشته می‌شود.
محدودیت: WARP تضمین نمی‌کند هر CAPTCHA تأیید شود؛ Cookie، JavaScript، Fingerprint و سیاست خود سایت نیز مؤثرند.
IR

سازگاری Tor با سرور ایران / شبکه محدود

Direct برای حالت عادی و obfs4 برای شبکه‌ای که bootstrap مستقیم Tor مسدود است.

نکته: فعال‌کردن Bridge بدون Bridge معتبر باعث می‌شود Tor instanceها بالا نیایند.
